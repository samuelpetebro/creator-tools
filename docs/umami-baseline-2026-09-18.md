## CI traffic note

The current GitHub Actions checks do not explain production Umami sessions:

- browser smoke runs against `127.0.0.1`; `analytics.js` refuses to load tracking unless `location.hostname === 'droopweb.lat'`
- production smoke uses Node `fetch()` and does not execute browser JavaScript

Therefore, USA sessions visible in Umami are not generated by these two smoke workflows. They still should not automatically be treated as confirmed human users; external bots/headless browsers and other automated clients can exist.
